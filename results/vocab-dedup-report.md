# vocab dedup report — retracted, see vocab-collision-report.md

Lane: `ghoul-sonnet-vocabfix`.

The original task instructed this lane to *repair* de/zh duplicate tokens
(pick a distinct word, or set `null` + notes). The operator retracted this
mid-lane after re-measuring the collision groups directly: only 12 of the
54 de collision groups are id-prefix-related "design split" candidates
(e.g. `calendar`/`calendar_daily`); the other 42 — and nearly all of the 44
zh groups — are genuine lexical gaps where German/Chinese has one real,
attested word for two related English/Japanese concepts (`Nebel` = fog and
nebula, `Holz` = wood and the classical wood-element, `Opfer` = religious
offering, sacrifice, and victim). Coining a second distinct word where none
exists would be fabrication — the one unrecoverable/capital-offense error
in this dataset's own schema law.

**Replacement rule, implemented instead:** collisions are annotated
(`token_collision` field, generated by `scripts/build_vocab.py`), not
repaired. `scripts/validate_vocab.py` enforces that every real collision is
correctly annotated; the collision's mere existence is not a violation.
Full enumeration, design-split-vs-true-collision classification, and the
downstream-distance-must-be-UNDEFINED-not-0 consequence are all in
`results/vocab-collision-report.md`.

## Two entries that *were* reverted, not merely annotated

During the D-notation repair pass (moving `(disambiguator)` parentheticals
out of `en` tokens into `notes`), two auto-fixes were caught and reverted
by the pre-existing (ja,en)-pair uniqueness check:

| id | domain | before | attempted after | why reverted |
|----|--------|--------|------------------|---------------|
| `fish_food` | daily | en=`fish (food)` | en=`fish` | ja/de/zh already collided with `fish` (cosmology); the `(food)` parenthetical was the *only* remaining distinguishing signal across all 4 language columns. Stripping it collapsed the two into full duplicates. |
| `pet_daily` | daily | en=`pet (animal)` | en=`pet` | same failure mode against `pet` (relations); ja/de/zh already collided. |

Both were restored to their original bracketed `en` value and left in the
token-notation-violation list (`scripts/validate_vocab.py` still flags
them) rather than force-fixed — this is exactly the "if stripping changes
meaning, don't; report and leave as-is" fallback from lane law.

No other de/zh token was changed by this lane. See
`results/vocab-collision-report.md` for the full audit.
